## 1. الملخص التنفيذي

MGF هو منصة SaaS على الويب تعالج مشكلة أساسية في المحتوى البصري المولد بالذكاء الاصطناعي: نماذج الذكاء الاصطناعي قد تخترع تخطيطات غير دقيقة، أو تتجاهل عناصر، أو تنتج مخرجات يصعب تعديلها أو إعادة استخدامها. يقدم MGF **إطار توليد معياري** يفصل المحتوى، والتخطيطات ذات المكونات البسيطة، والثيم إلى ملفات مستقلة يمكن استدعاؤها بشكل منفصل، ما يجعل التوليد أكثر موثوقية وقابلية للتنبؤ والتركيب.

إضافة إلى التوليد، يمثل MGF **نظاما مجتمعيا للقوالب** حيث يستطيع المستخدمون مشاركة القوالب ونسخها وتعديلها كمشاريع، بطريقة مشابهة لتفرع المستودعات في GitHub. النتيجة هي دمج لثلاثة نماذج:

> **GitHub** - نسخ القوالب وإصدارها ومشاركتها كمشاريع  
> **Canva** - تخصيص خصائص CSS من لوحة جانبية وتصدير بصري جميل  
> **AI-native** - توليد معياري عبر أي LLM، سواء سحابي أو محلي

بالإضافة إلى الموقع الكامل، سيحتوي الموقع أيضا على قاعدة بيانات مجتمعية لمشاركة الموارد مثل: البرومبتات، المهارات، الوكلاء، MCP، ملفات التصميم بصيغة md، وغيرها.

## 2. بيان المشكلة

### نقاط الألم الحالية

| نقطة الألم                              | الوصف                                                                                                                     |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **الذكاء الاصطناعي يتجاهل عناصر**       | عند طلب توليد عرض تقديمي أو ملصق كامل، غالبا ما يتجاوز بعض المكونات، أو يتجاهل قواعد التخطيط، أو ينتج أسلوبا غير متسق.    |
| **المخرجات كتلة واحدة**                 | الملفات المولدة مثل HTML أو PPTX أو PDF يصعب تعديل جزء منها فقط؛ غالبا يجب إعادة توليد كل شيء أو تعديل الكود الخام يدويا. |
| **لا يوجد فصل للمسؤوليات**              | المحتوى والتخطيط وبنية المكونات متداخلة؛ تغيير جزء قد يكسر الأجزاء الأخرى.                                                |
| **لا توجد قابلية لإعادة الاستخدام**     | كل عملية توليد تبدأ من الصفر؛ لا توجد طريقة منظمة لمشاركة القوالب أو نسخها أو البناء فوق قوالب الآخرين.                   |
| **الاعتماد على مزود ذكاء اصطناعي واحد** | معظم الأدوات مرتبطة بمزود واحد؛ تغيير النموذج يعني خسارة سير العمل.                                                       |
| **تعديل الملفات المولدة صعب**           | تعديل HTML أو PPTX أو PDF الخام يتطلب معرفة تقنية لا يملكها معظم المستخدمين.                                              |

### السبب الجذري

المشكلة الأساسية هي أن الأدوات الحالية تتعامل مع توليد المحتوى البصري كأنه **صندوق أسود بضربة واحدة**: برومبت واحد يدخل، وملف واحد كبير يخرج. هذا النموذج يفشل عند التوسع ويصعب تحسينه بالتكرار.

## 3. الرؤية والأهداف

### الرؤية

أن تصبح MGF المنصة القياسية للمحتوى البصري المنظم والمولد بالذكاء الاصطناعي، بحيث يستطيع أي مستخدم، سواء طالب أو مدرس أو صانع محتوى أو شركة، إنتاج مخرجات احترافية من خلال سير عمل يبدأ من القوالب ومدعوم بالذكاء الاصطناعي والمجتمع.

### أهداف MVP

1. تأسيس **نموذج الملفات المعيارية**: فصل المحتوى + التخطيط + المكونات + الثيم.
2. تمكين **التوليد بالذكاء الاصطناعي** عبر واجهات خارجية ونماذج محلية مثل LM Studio.
3. بناء **لوحة جانبية لتخصيص خصائص CSS** لتحرير المخرجات على الويب.
4. إطلاق **مجتمع القوالب**: مشاركة، نسخ، وإعادة مزج القوالب.
5. دعم **عدة صيغ تصدير** مثل HTML وPDF وPNG وغيرها.

### مؤشرات النجاح (MVP)

- يستطيع المستخدم توليد مخرج بصري كامل خلال أقل من 3 دقائق.
- يستغرق مسار نسخ القالب ثم تحريره أقل من 60 ثانية.
- دعم أنواع مختلفة من المشاريع مثل: موقع ويب، كاروسيل، منشور واحد، عرض تقديمي، إنفوجرافيك.
- تعمل المنصة مع 3 مزودين مختلفين على الأقل لنماذج LLM، مثل OpenAI وAnthropic ونموذج محلي عبر LM Studio.
- وجود مكتبة بداية تضم أكثر من 20 قالبا مجتمعيا عند الإطلاق.

## 5. المفاهيم الأساسية

### 5.1 نموذج الملفات المعيارية (غير نهائي وقابل للتعديل والتحديث)

كل مشروع أو قالب في MGF يتكون من طبقات ملفات منفصلة وقابلة للتحرير بشكل مستقل:

```text
project/
├── content.json        # المحتوى النصي/البياني الفعلي: ماذا نقول
├── sequance.json       # قواعد البنية والتسلسل: كيف يتم الترتيب، للمشاريع وليس للقوالب
├── slides(or) pages/   # كتل واجهة قابلة لإعادة الاستخدام: عناوين، بطاقات، إلخ
│   ├── hero.html
│   ├── title1.html
│   └── conclusion.html
├── style.css           # التنسيق البصري: الألوان، الخطوط، المسافات
├── layout.css          # CSS متعلق بالتخطيط: padding, margin, alignment
├── context.md          # تعليمات توليد الذكاء الاصطناعي / سياق البرومبت
├── rules.md            # قيود وقواعد التوليد
└── meta.json           # بيانات المشروع: الاسم، الوسوم، نوع المخرج، إلخ
```

**المبدأ الأساسي:** يمكن استدعاء الذكاء الاصطناعي لإعادة توليد **أي طبقة واحدة** دون لمس الطبقات الأخرى. يمكن تغيير المحتوى دون لمس التخطيط، أو تغيير التخطيط دون لمس المكونات.

### 5.2 أنواع المخرجات

يدعم MGF أنواع المخرجات البصرية التالية ضمن نطاق MVP:

| نوع المخرج       | الوصف                                                 |
| ---------------- | ----------------------------------------------------- |
| عرض تقديمي       | مجموعة شرائح متعددة مثل PowerPoint أو Google Slides.  |
| كاروسيل اجتماعي  | بطاقات متسلسلة قابلة للتمرير مثل Instagram وLinkedIn. |
| ملصق             | تصميم صفحة واحدة مثل A4 أو أحجام مخصصة.               |
| إنفوجرافيك       | سرد بصري قائم على البيانات.                           |
| مستند            | مستند منظم كثير النصوص مع تحسين بصري.                 |
| موقع / صفحة هبوط | مخرج ويب بصفحة واحدة HTML + CSS.                      |

### 5.3 القالب مقابل المشروع

| المفهوم     | الوصف                                                                                                                |
| ----------- | -------------------------------------------------------------------------------------------------------------------- |
| **القالب**  | أساس مشترك في المجتمع يحدد البنية والأسلوب. للآخرين يكون للقراءة فقط، ويمكن نسخه.                                    |
| **المشروع** | نسخة شخصية للمستخدم من قالب. قابلة للتحرير بالكامل. يمكن جعلها عامة وربما إعادة مشاركتها كقالب وفق قواعد تحدد لاحقا. |

### 5.4 أوضاع التوليد

| الوضع              | الوصف                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------ |
| **التوليد الكامل** | الذكاء الاصطناعي يولد كل الملفات من برومبت + سياق.                                         |
| **التوليد الجزئي** | الذكاء الاصطناعي يعيد توليد طبقة واحدة فقط، مثل content.md.                                |
| **التحرير اليدوي** | المستخدم يحرر أي ملف يدويا عبر لوحة تخصيص خصائص CSS الجانبية أو المحرر الخام.              |
| **الرفع والحقن**   | المستخدم يرفع محتوى مشروع قائم يطابق البنية المطلوبة، ثم يكيفه الذكاء الاصطناعي مع القالب. |

### 6.7 قاعدة بيانات المجتمع (قوالب Bracket)

| النوع          | الوصف                                                                  |

| برومبتات الصور | قوالب برومبت لتوليد الصور.                                             |

| ملفات القواعد  | ملفات قيود التوليد.                                                    |
| إعدادات MCP    | إعدادات Model Context Protocol.                                        |

يمكن للمستخدمين تصفح قاعدة البيانات المجتمعية واستخدامها والمساهمة فيها.

## 7. قصص المستخدم

### المسار الأساسي

**بصفتي صانع محتوى،** أريد تصفح قوالب المجتمع ونسخ قالب كاروسيل لوسائل التواصل، حتى أبدأ من بنية مثبتة وأخصصها لهويتي.

**بصفتي طالبا،** أريد كتابة موضوع بحثي ليولد الذكاء الاصطناعي عرضا تقديميا كاملا من قالب جامعي، حتى أحصل على نقطة بداية احترافية دون قضاء ساعات في التصميم.

**بصفتي مطورا،** أريد استدعاء MGF API من نسخة LM Studio المحلية لدي، حتى أؤتمت توليد المحتوى ضمن خط المعالجة الخاص بي.

**بصفتي مدرسا،** أريد نشر قالب شرائح المحاضرات الخاص بي للمجتمع، حتى يستطيع الطلاب نسخه واستخدام نفس التنسيق المتسق.

**بصفتي مستخدم أعمال،** أريد إعادة توليد طبقة المحتوى فقط في عرض الاستثمار بعد تحديث البيانات المالية، حتى لا أعيد التصميم.

**بصفتي أي مستخدم،** أريد تصدير مشروعي النهائي بصيغتي PDF وHTML، حتى أستخدمه في أكثر من سياق: الطباعة والويب.

## 10. نطاق MVP

### داخل النطاق (MVP)

- مصادقة المستخدم: بريد إلكتروني + Google OAuth.
- CRUD للمشاريع والقوالب.
- محرر ملفات معياري: لوحة تخصيص خصائص CSS الجانبية + محرر خام.
- محرك توليد بالذكاء الاصطناعي: APIs خارجية + محلي.
- معرض قوالب المجتمع: تصفح، نسخ، بحث.
- التصدير: HTML وPDF وPNG وZIP وMarkdown.
- أنواع المخرجات: عرض تقديمي، ملصق، كاروسيل اجتماعي، مستند.
- مكتبة قوالب Bracket المجتمعية بشكل أساسي.
- ملفات المستخدمين ونسبة القوالب للمؤلفين.
- CRUD للموارد مثل البرومبتات والمهارات وMCP والوكلاء.
- تصدير PPTX مخطط له في v1.1.
- نوع مخرج Website/Landing Page مخطط له في v1.1.

### خارج النطاق (بعد MVP)

- التعاون الفوري متعدد المستخدمين.
- الدفع أو الاشتراكات.
- الإشعارات الفورية.
- تطبيق جوال أصلي.
- إصدار متقدم أو فروقات شبيهة بـ Git.
- سوق قوالب مع تحقيق دخل.
- مخرجات الفيديو أو التحريك.
- تكامل النماذج المضبوطة Fine-tuned.

## 12. الافتراضات والقيود

- لا يوجد نظام دفع أو فوترة في MVP.
- لا توجد ميزات فورية مثل WebSockets في MVP.
- المستخدمون يجلبون مفاتيح API الخاصة بهم لتوليد الذكاء الاصطناعي، ولا توجد ميزانية API مشتركة في MVP.
- يجب أن تعمل المنصة مع APIs سحابية ونماذج محلية عبر endpoints متوافقة مع OpenAI.
- يتكون الفريق من مطوري Laravel للخلفية ومطوري React/TypeScript للواجهة الأمامية.
