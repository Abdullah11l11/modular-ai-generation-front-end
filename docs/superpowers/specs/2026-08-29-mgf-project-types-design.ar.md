## 1. الهدف

عمل على الواجهة الأمامية فقط. نريد عرض وتوليد عدة أنواع من مخرجات المشروع، لكل منها تخطيطه وحجمه الافتراضي وأحجامه المسموحة وتلميحات تصديره. **بدون أي تغيير على الواجهة الخلفية أو عقد API** — كل ما يلي يُنفَّذ على الواجهة الأمامية فقط.

قصة المستخدم التي تقود هذا العمل:

> **1- انواع مشاريع (احجام وتفاصيل تانية) مشان نقدر نعرض كذا نوع**

نسخة إنجليزية من هذا المستند متوفرة في `2026-08-29-mgf-project-types-design.md`.

## 2. المفاهيم

- **النوع (الكتالوج)** — قائمة `GET /types` الثابتة التي تعيدها الواجهة الخلفية (`presentation`، `carousel`، `poster`، `website`، `infographic`، `document`...). لكل نوع `id` و`name` و`description` و`icon`.
- **التخطيط archetype** — محرك التخطيط المستخدم لعرض المعاينة. `docs/design-system.md` §4 يعرّف التخطيطات. من هذا الكتالوج نستخدم **`deck`** و**`single`** و**`website`**.
- **الحجم الافتراضي** — نسبة العرض/الارتفاع أو حجم الصفحة الذي يبدأ به النوع.
- **الأحجام المسموحة** — نطاق الأحجام التي يقدمها المحرر/التصدير لذلك النوع.
- **تلميحات التصدير** — أي صيغ تصدير منطقية لذلك النوع.

## 3. جدول التطابق المؤكد (هذا ما عملنا عليه)

هذا الجدول هو مصدر الحقيقة. يُنفَّذ كثابت مكتوب **في الواجهة الأمامية فقط** — دون أي تغيير على عقد API.

| النوع (الكتالوج) | التخطيط | الحجم الافتراضي | الأحجام المسموحة | تلميحات التصدير |
| --- | --- | --- | --- | --- |
| عرض تقديمي presentation | deck | 16:9 | 16:9، 3:4 | PDF، PPTX، سلسلة PNG، HTML، ZIP |
| كاروسيل carousel | deck | full | full، square | سلسلة PNG، HTML، ZIP |

| موقع/صفحة هبوط website | website | full | full | HTML، ZIP |
| إنفوجرافيك infographic | website | full | full | PNG، PDF، HTML |
| مستند document | website | A4 | A4 | PDF، HTML |

## 4. نطاق الواجهة الأمامية

### ضمن النطاق

- **واجهة اختيار الأنواع** (مشروع جديد) — عرض كتالوج `GET /types` كبطاقات باستخدام `name` و`description` و`icon`. اختيار نوع يملأ مسبقا التخطيط والحجم الافتراضي وتلميحات التصدير من جدول §3.
- **محدد الحجم** — أداة تحكم واعية بالتخطيط مربوطة بـ `allowedSizes` للنوع المختار. تظهر عندما يدعم النوع عدة أحجام (مثل `presentation` → 16:9 / 3:4)؛ وتُخفى عندما يكون الحجم `full` فقط.
- **لوحة التفاصيل** — ملخص مكثف (شارة النوع، شارة التخطيط، الحجم الحالي، تلميحات التصدير) يظهر في رأس/بطاقات المشروع.
- **التصفية** — لوحة المتابعة/معرض القوالب يمكنه التصفية حسب النوع باستخدام بارامتر `type_id` الموجود، وبحجم/تخطيط محليا.
- **بنية تحتية للأنواع** — هوك `useTypes()` ودالة `listTypes` تحت `features/types`، إضافة إلى نوع FE مشترك يمثل جدول §3.

### خارج النطاق

- أي تغيير على مخطط الواجهة الخلفية أو عقد API.
- تحرير محتويات الشرائح داخل كل تخطيط (مهمة المحرر).
- تخطيطات جديدة بعد `deck` / `single` / `website` المستخدمة في هذا الكتالوج.

### الملفات (مقترح)

| المسار | الغرض |
| ------ | ----- |
| `src/features/types/api/listTypes.ts` | استدعاء `GET /types`. |
| `src/features/types/hooks/useTypes.ts` | هوك TanStack Query يغلف `listTypes`. |
| `src/features/types/types/outputType.ts` | أنواع FE + جدول §3 كثابت مكتوب. |
| `src/features/types/components/TypePicker.tsx` | شبكة بطاقات لاختيار نوع المشروع عند الإنشاء. |
| `src/features/types/components/SizeSelector.tsx` | أداة تحكم بالحجم واعية بالتخطيط. |
| `src/features/types/components/TypeBadge.tsx` | شارة (نوع + تخطيط) للرأس/البطاقات. |

### الربط

- **تدفق إنشاء المشروع** (`features/projects`) يستخدم `TypePicker` → يرسل `type_id` (الحجم/التخطيط مشتقان محليا من ثابت §3).
- **صفحة تفاصيل القالب** و**لوحة المتابعة** تعرضان `TypeBadge` وتصفّيان حسب النوع/الحجم محليا.
- إبقاء تركيب المشروع/المحرر في مجلداتها الخاصة حسب `docs/FRONTEND_STRUCTURE_GUIDE.md`.
